# 账本

一个纯前端的记账 PWA（渐进式网页应用），可以“添加到主屏幕”像 App 一样使用，支持离线、两人共享账本和端到端加密同步。没有构建步骤，没有后端代码，改完文件直接推送即可上线。

## 功能

- 记账：收入 / 支出、分类与子分类、支付方式、备注、多币种与汇率、预算
- 定期记账、目标（存钱）、心愿单、纪念日
- 统计、月度回顾、分享卡片、截图识别记账
- 两人共享账本（共同账本 + 各自私人账本），数据加密后同步
- 撤销、本地备份（`ledger.bak`）、数据导出

## 目录结构

```
.
├── index.html        页面骨架，只负责引用下面的文件
├── manifest.json     PWA 配置（名称、图标、主题色）
├── sw.js             Service Worker：离线缓存，网络优先、断网回退缓存
├── css/
│   └── style.css     全部样式（含浅色 / 深色主题）
├── js/
│   ├── sync.js       同步层：加密、Firebase REST 读写、同步码
│   └── app.js        主程序：数据、界面渲染、各功能
└── img/              应用图标与头像
```

脚本加载顺序：`js/sync.js`（在 `<head>`，同步执行）→ `js/app.js`（在 `<body>` 末尾）。`sync.js` 定义了全局的 `db`、`user`、`dl` 等对象，`app.js` 依赖它们，顺序不能调换。

## 本地运行

没有依赖，任意静态服务器即可，例如：

```bash
npx serve .
```

注意：Service Worker 只能在 `https` 或 `localhost` 下注册，直接双击打开 html 文件可以看到界面，但离线缓存和分享卡片生成可能不可用。

## 部署

部署在 GitHub Pages：仓库 **Settings → Pages**，Source 选 `main` 分支、`/ (root)`。推送到 `main` 后一两分钟自动更新。

### 更新后手机没变化？

`sw.js` 会缓存文件。每次改动静态文件后，把 `sw.js` 里的缓存名（`ledger-vN`）加一，手机重新打开两次即可拿到新版本。

## 同步

数据存放在你自己的 Firebase Realtime Database，通过它的 REST 接口读写。

1. 在 Firebase 控制台创建 Realtime Database，复制网址（形如 `https://xxx-default-rtdb.firebaseio.com`）。
2. 在 App 的 **设置 → 同步设置** 填入：数据库网址、共同密码、自己的名字。
3. 两人的网址和密码必须相同，名字必须不同。

也可以用**同步码**：在已连接的设备上点“复制同步码 / 复制同步链接”，发给对方。对方粘贴或点开后网址和密码自动填好，只需填自己的名字。

### 加密方式

- 共同密码经 PBKDF2（SHA-256，10 万次迭代）派生出 AES-GCM 256 位密钥
- 数据在本机加密后才上传，服务器只存密文
- 同步空间 ID 是密码的 SHA-256 前 32 位，知道密码才能找到同一个空间
- 私人账本不上传，只存在本机

### 同步码的安全提醒

同步码里包含密码，等于账本的钥匙，只发给信任的人。它只是编码，不是加密。

## 数据存放

| 位置 | 内容 |
| --- | --- |
| `localStorage` `ledger.fb` | 同步配置（网址、密码、名字） |
| `localStorage` 主数据 | 账本全部记录 |
| `localStorage` `ledger.bak` | 同步覆盖前的自动备份 |
| Firebase `/s/<空间ID>/…` | 加密后的共享数据 |

localStorage 跟着网址走，换域名后是一个空的账本，需要重新填同步设置，私人账本要先导出再导入。

## 已知限制

- 同一条记录被两台设备同时修改时，取最后修改的一次（新增、删除不会互相覆盖）
- 同步空间 ID 没有加盐，密码太简单时有被离线暴力破解的风险，请使用较长的密码
- Firebase 规则请在控制台检查，避免使用对所有人开放读写的规则
